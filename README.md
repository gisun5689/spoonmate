# SpoonMate Remote Authorization

This public repository builds and publishes SpoonMate's signed authorization policy.

Public endpoint:

`https://gisun5689.github.io/spoonmate/authorization-envelope.json`

## Management files

- `config/users.json`: administrator-edited Spoon UID allowlist
- `authorization-public-key.pem`: Ed25519 public key embedded in SpoonMate
- `scripts/build-authorization.mjs`: validates the allowlist and signs a new envelope
- `scripts/verify-authorization.mjs`: strictly verifies the signature and payload schema
- `.github/workflows/pages.yml`: builds, verifies and deploys the public files
- `authorization-envelope.json`: legacy signed snapshot; the live Pages artifact is generated by Actions

## One-time GitHub Secret setup

Create this repository secret before merging the management workflow:

`Settings → Secrets and variables → Actions → New repository secret`

- Name: `AUTHORIZATION_ED25519_PRIVATE_KEY_BASE64`
- Value: the complete Base64 text from the protected private-key secret file

The decoded private key must match `authorization-public-key.pem`. The workflow deliberately fails before deployment when the secret is missing, malformed or mismatched.

## Add a user

Edit `config/users.json` and append a user object:

```json
{
  "spoon_uid": "NEW_SPOON_UID",
  "enabled": true,
  "expires_at": null
}
```

Commit the change to `main`. GitHub Actions then:

1. validates the registry;
2. creates a new revision and canonical UTC issue time;
3. signs the payload with the protected Ed25519 private key;
4. verifies the new envelope with the committed public key;
5. deploys only the verified artifact to GitHub Pages.

SpoonMate checks UID only. Nickname and TAG are not authorization identifiers.

## Disable or expire a user

- Immediate block: set `"enabled": false`
- No expiration: set `"expires_at": null`
- Timed expiration: use canonical UTC ISO time, for example `"2026-12-31T14:59:59.000Z"`

Do not delete a user merely to block access; disabling preserves an auditable registry history.

## Change the minimum app version

Update `minimum_app_version` in `config/users.json`, for example:

```json
"minimum_app_version": "2.0.15.5"
```

## Never commit

- Ed25519 private keys or signing bundles
- the value of `AUTHORIZATION_ED25519_PRIVATE_KEY_BASE64`
- GitHub tokens, API secrets, passwords or environment files
- SpoonMate DEV source, encrypted source bundles or Distribution packages

Do not manually edit `payload_base64` or `signature_base64`. They are generated artifacts and any hand edit invalidates the signature.
