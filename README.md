# SpoonMate Remote Authorization

This public repository builds and publishes SpoonMate's signed authorization policy, Ed25519 public key, and public LITE update-version metadata.

## Public endpoints

Public authorization endpoint:

`https://gisun5689.github.io/spoonmate/authorization-envelope.json`

Public LITE update metadata endpoint:

`https://gisun5689.github.io/spoonmate/lite-update.json`

## Management files

- `config/users.json`: administrator-edited Spoon UID authorization registry
- `authorization-public-key.pem`: Ed25519 public key embedded in SpoonMate
- `lite-update.json`: public LITE latest-version metadata used before GitHub Release lookup
- `scripts/build-authorization.mjs`: validates the UID registry and generates a newly signed authorization envelope
- `scripts/verify-authorization.mjs`: strictly verifies the authorization signature and payload schema
- `.github/workflows/pages.yml`: builds and verifies authorization, verifies LITE metadata, and deploys public files to GitHub Pages
- `authorization-envelope.json`: legacy signed snapshot in the repository; the live Pages authorization envelope is generated by GitHub Actions

## One-time GitHub Secret setup

Create the repository secret:

`Settings → Secrets and variables → Actions → New repository secret`

- Name: `AUTHORIZATION_ED25519_PRIVATE_KEY_BASE64`
- Value: the complete Base64 text from the protected private-key secret file

The decoded private key must match `authorization-public-key.pem`.

The workflow deliberately fails before deployment when the secret is missing, malformed, or does not match the committed public key.

## Add a user

Edit `config/users.json` and append a user object:

```json
{
  "spoon_uid": "NEW_SPOON_UID",
  "enabled": true,
  "expires_at": null
}
```

Commit the change to `main`.

GitHub Actions then:

1. validates `config/users.json`;
2. creates a new authorization revision and issue time;
3. signs the payload with the protected Ed25519 private key;
4. verifies the generated envelope with `authorization-public-key.pem`;
5. verifies the LITE update metadata;
6. deploys the verified authorization envelope, public key, LITE metadata, and public page to GitHub Pages.

SpoonMate authorization checks Spoon UID only.

Nickname and TAG are not authorization identifiers.

## Disable or expire a user

Immediate block:

```json
"enabled": false
```

No expiration:

```json
"expires_at": null
```

Timed expiration uses canonical UTC ISO time, for example:

```json
"expires_at": "2026-12-31T14:59:59.000Z"
```

Do not delete a user merely to block access. Disabling the user preserves the authorization registry history.

## Change the minimum app version

Update `minimum_app_version` in `config/users.json`, for example:

```json
"minimum_app_version": "2.0.15.31"
```

Do not raise the minimum version above the currently distributed SpoonMate version until the corresponding installer is ready for users.

## LITE update metadata

`lite-update.json` contains public LITE update-version metadata.

It is version metadata only.

A real automatic update is downloadable only after the verified Windows installer, blockmap, and `lite.yml` are published in a GitHub Release.

## Never commit

- Ed25519 private keys or signing bundles
- the value of `AUTHORIZATION_ED25519_PRIVATE_KEY_BASE64`
- GitHub tokens, API secrets, passwords, or environment files
- SpoonMate DEV source
- encrypted source bundles
- Distribution packages

Do not manually edit `payload_base64` or `signature_base64`.

They are generated artifacts, and any manual modification invalidates the Ed25519 signature.
